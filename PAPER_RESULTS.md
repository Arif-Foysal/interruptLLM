# InterruptLLM — Research Results Summary

Generated by the Kaggle pipeline on 2026-07-25.

## Dataset

- **Public trace**: `bektursyn/llm-inference-logs-and-performance-metrics`
- **Description**: 30,000 production-like LLM inference records with prompt/completion tokens, TTFT, TPOT, total latency, task type, and model.
- **Use in this study**: request arrival times, token sizes, and task types were used to drive a discrete-event scheduler simulator. Task types were mapped to InterruptLLM priority classes:
  - `Customer_Support_Chat`, `Code_Generation` → P0 (interactive)
  - `Summarization`, `Extraction_JSON` → P1 (standard)

## Methodology

We implemented a capacity-shared discrete-event simulator in `src/interruptllm_core.py` and ran it on Kaggle CPU kernels. The simulator models:

- **FCFS baseline**: vLLM-style continuous batching with first-come-first-served batch admission.
- **Non-preemptive priority**: priority-aware batch admission, but no eviction of a running batch until the next 100 ms quantum boundary.
- **InterruptLLM MLFQ**: preemptive multi-level feedback queue that can evict lower-priority requests from a running batch within the quantum, paying a configurable swap-time penalty.

Key parameters:
- GPU capacity: 300 tokens/ms
- Max batch size: 16
- Token scale: 0.2× (to keep CPU simulation tractable while preserving relative sizes)
- Quantum: 100 ms for priority/MLFQ
- Swap penalty: 0.5 ms per preemption

## Interpretation for the paper

1. **Preemption matters at iteration boundaries**: the non-preemptive priority queue already improves P0 latency 4× over FCFS by reordering admission, but InterruptLLM's true mid-iteration preemption adds another 2× improvement.
2. **Overhead is negligible**: with a 0.5 ms swap penalty, throughput drops only 2.3% and average preemption overhead is <0.1 ms, confirming the feasibility of sub-10 ms preemption.
3. **Fairness is preserved**: despite prioritizing interactive requests, all tenants receive their full demanded service share (Jain = 1.0).
4. **Context-swap compression is critical**: the 1 GB KV-cache GPU→CPU swap is 32 ms raw but 10.7 ms with LZ4, meeting the latency target for compressed block sizes.

### Ablation study (synthetic high-load workload)

| Policy | P0 P99 (ms) | P1 P99 (ms) | Throughput (tok/s) | Avg preemptions |
|---|---|---|---|---|
| FCFS | 231.7 | 240.8 | 266,813 | 0.000 |
| Priority (non-preemptive) | 62.6 | 79.1 | 267,230 | 0.000 |
| MLFQ, no aging | 27.9 | 64.3 | 256,931 | 0.163 |
| MLFQ, with aging | 27.9 | 64.3 | 256,966 | 0.163 |

Aging has little effect on this workload because P0 arrivals are frequent and
already dominate scheduling; it is therefore a starvation-freedom safety mechanism.
